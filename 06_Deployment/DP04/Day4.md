1. Streamlit의 스크립트 재실행 모델이란 무엇입니까?

사용자가 버튼을 누르거나 입력을 바꿀 때마다 파이썬 스크립트가 처음부터 끝까지 다시 실행됩니다.

2. st.text_input()에 값을 입력하면 내부적으로 어떤 일이 일어납니까?  
: 위에서부터 스트립트 전체가 다시 실행, 새로 입력한 값이 st.text_input()함수를 통해 변수에 새롭게 할당

3. st.set_page_config()를 스크립트 중간에 호출하면 어떻게 됩니까?  
: 에러(StreamlitAPIException)가 발생하여 앱이 실행되지 않습니다. st.set_page_config() 명령은 페이지의 기본 레이아웃과 제목 등을 설정하는 기능이므로, 반드시 스크립트 내에서 다른 모든 Streamlit 함수들보다 가장 먼저 호출되어야 합니다.


✅ 체크포인트  
1. st.file_uploader()로 업로드된 파일의 바이트 데이터는 어떻게 얻습니까?  
: 업로드된 파일 객체의 getvalue() 메서드를 호출하여 바이트 형태의 데이터를 추출할 수 있습니다.  

2. Streamlit에서 @st.cache_resource를 사용하는 이유는 무엇입니까?  
: Streamlit은 이벤트마다 스크립트를 재실행한다고 했습니다. 매번 재실행할 때마다 객체를 다시 생성하면 느려지므로, 한 번만 생성하고 재사용하는 캐시가 필요합니다. @st.cache_resource를 사용하면 API 클라이언트를 캐시하는 용도로만 사용합니다. 모델은 FastAPI 서버가 관리하므로, Streamlit에서 모델을 로드할 일은 없습니다.

✅ 체크포인트  
1. 이미지를 API에 전송할 때 Base64로 인코딩하는 이유는 무엇입니까?  
: FastAPI와 같은 REST API 서버와 데이터를 주고받을 때 주로 사용하는 JSON 형식은 텍스트 기반이므로, 이미지 파일과 같은 원시 바이너리(Binary) 데이터를 직접 담을 수 없습니다. Base64 인코딩은 이러한 바이너리 데이터를 안전한 일반 텍스트 문자열(ASCII)로 변환해 주기 때문에, JSON 데이터 내에 포함시켜 웹을 통해 API 서버로 안전하게 전송할 수 있게 해줍니다.  
2. response.raise_for_status()는 어떤 역할을 합니까?  
: 파이썬의 requests 라이브러리로 API를 호출했을 때, 서버로부터 받은 응답의 HTTP 상태 코드를 확인하여 요청이 실패했을 경우(400번대 클라이언트 에러 또는 500번대 서버 에러) 즉시 HTTPError 예외(Exception)를 발생시키는 역할을 합니다. 만약 요청이 성공(200번대)했다면 아무 일도 일어나지 않으며, 에러가 발생하면 코드 흐름을 바로 except 블록으로 넘겨주어 안전한 에러 처리를 가능하게 합니다.  


✅ Day 4 최종 체크포인트  
[섹션 1: Streamlit 소개]  
Q1. Streamlit의 스크립트 재실행 모델이란?  
: Streamlit은 사용자가 버튼을 누르거나 입력값을 변경할 때마다 Python 스크립트를 위에서 아래까지 다시 실행한다. 변경된 위젯값을 이용하여 화면을 다시 구성하므로 별도의 프론트엔드 이벤트 처리 코드를 복잡하게 작성하지 않아도 된다.  

[섹션 2: 핵심 컨셉]  
Q2. @st.cache_resource를 사용하는 이유는?  
: Streamlit은 사용자 입력이 바뀔 때마다 스크립트를 재실행한다. 이때 API 클라이언트, 데이터셋, 모델처럼 생성 비용이 큰 객체를 매번 다시 만들면 속도가 느려진다.  

`@st.cache_resource`를 사용하면 객체를 처음 한 번만 생성하고 이후 재실행에서 같은 객체를 재사용할 수 있다.  
이번 실습에서는 HTTP 세션과 MNIST 테스트 데이터셋을 재사용하는 데 활용했다.

[섹션 3: System Architecture]  
Q3. 프론트엔드와 백엔드를 분리하는 핵심 이유 두 가지는?  
: 첫째, 프론트엔드와 백엔드를 독립적으로 개발하고 배포할 수 있다. 화면만 수정할 때는 Streamlit만 변경하고, 모델이나 추론 로직을 수정할 때는 FastAPI 서버만 변경할 수 있다.  
  
둘째, 하나의 FastAPI 서버를 Streamlit뿐 아니라 모바일 앱, 웹 애플리케이션, 다른 서버 등 여러 클라이언트가 함께 사용할 수 있다.  

Q4. Streamlit 앱에 PyTorch가 필요 없는 이유는?  
: 모델 로드, 이미지 전처리, PyTorch 추론은 FastAPI 백엔드가 담당한다. Streamlit은 이미지를 Base64 문자열로 변환해 HTTP 요청을 보내고, 반환된 JSON 결과를 화면에 표시한다.  

따라서 프론트엔드가 샘플 MNIST 데이터를 직접 불러오는 기능을 제외하면 모델 추론을 위해 PyTorch를 알거나 직접 사용할 필요가 없다.  

[섹션 4: API 호출]  
Q5. API 호출 실패 시 사용자에게 스택 트레이스가 아닌 메시지를 보여줘야 하는 이유는?  
: 스택 트레이스에는 서버 코드 경로, 라이브러리 정보, 내부 구현과 같은 민감한 정보가 포함될 수 있어 보안상 위험하다. 또한 일반 사용자가 이해하기 어렵다.  

따라서 상세 오류는 서버 로그에 기록하고, 사용자에게는 `서버에 연결할 수 없습니다`, `응답 시간이 초과되었습니다`와 같이 안전하고 이해하기 쉬운 메시지를 보여줘야 한다.  

[섹션 5: 실습]  
Q6. st.session_state에 결과를 저장하는 이유는?  
: Streamlit은 버튼을 누르거나 위젯값이 변경될 때마다 스크립트를 다시 실행한다. 일반 변수에만 결과를 저장하면 다음 재실행에서 결과가 사라질 수 있다.  

`st.session_state`에 추론 결과와 샘플 이미지 정보를 저장하면 스크립트가 재실행되어도 이전 결과를 유지할 수 있다.  

Q7. 이미지를 API로 전달할 때 Base64 인코딩이 필요한 이유는?  
: JSON은 이미지의 원본 바이트 데이터를 직접 표현하기 어렵다. Base64 인코딩을 사용하면 이미지 바이트를 텍스트 문자열로 변환하여 JSON 요청에 안전하게 포함할 수 있다.  

Streamlit은 이미지를 Base64 문자열로 변환해 FastAPI에 전송하고, FastAPI는 문자열을 다시 이미지 바이트로 디코딩하여 전처리와 모델 추론을 수행한다.
