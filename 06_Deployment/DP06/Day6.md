1. 인증 없는 API가 위험한 이유를 두 가지 이상 설명하세요.  
- 서버다운 : 누군가가 초당 수백개의 요청을 쏟아내면 모델 추론은 CPU/GPU을 사용하기 때문에 서버가 과부하로 다운된다.   
- 비용폭탄 : GPU서버를 클라우드에서 운영하는데 인증없이 누구나 호출 가능하면 불특정 다수의 요청으로 GPU 사용량이 치솟는다.  
- 모델도용 : 공격자가 대량으로 입력-출력 쌍을 수집해 모델을 모방하는 모델을 학습   
- 추적불가 : 에러 발생했을때, 문제 원인을 파악할 수 없고 악의적 사용자 차단 불가  

2. API Key 방식이 ML 추론 API에 적합한 이유는 무엇입니까?  
: OpenAI, Anthropic, Hugging Face 등 대부분의 ML API가 이 방식을 사용합니다. 사용자 로그인이 필요 없고, 키 하나로 인증과 사용량 추적이 모두 가능하기 때문입니다.  


✅ 체크포인트

1. `Header(None)`에서 `None`은 어떤 상황에서 `x_api_key`에 들어갑니까?  
:   
요청의 X-API-Key 헤더 값을 x_api_key 변수에 넣습니다.  
헤더가 없으면 None이 됩니다.  
FastAPI가 자동으로 x_api_key → X-API-Key로 매핑합니다.    

2. `Depends(verify_api_key)`를 엔드포인트에 추가하면 요청 처리 흐름이 어떻게 바뀝니까?  
: FastAPI가 predict() 함수를 실행하기 전에, verify_api_key()를 먼저 실행해,  
verify_api_key()가 성공하면 → 반환값("사용자A")이 user 변수에 들어갑니다.  
   verify_api_key()가 HTTPException을 발생시키면 → predict()는 실행되지 않고 401이 반환됩니다.  


3. 인증 실패 시 반환하는 HTTP 상태 코드 401의 의미는 무엇입니까?  
:  HTTP 상태 코드 401(Unauthorized, 권한 없음) 에러  


✅ 체크포인트  
1. UploadFile과 Base64 방식의 핵심 차이는 무엇입니까?  
- Base64: 이미지를 텍스트로 인코딩하여 JSON 등 다른 데이터와 함께 하나의 요청(Request)에 담아 보낼 때 주로 사용합니다.  

- UploadFile: 파일을 독립적으로 직접 전송하는 방식입니다. 주로 파일 단독 업로드에 쓰이며, Swagger UI에서 파일 선택 버튼이 자동으로 제공되어 테스트하기 편리합니다.  

2. file.content_type으로 타입을 검증하는 이유는 무엇입니까?  
: 클라이언트가 보낸 파일이 text/plain과 같이 명백하게 엉뚱하고 지원하지 않는 형식인지 1차적으로 빠르게(비용을 적게 들여) 걸러내기 위해서입니다. (단, 이 값은 클라이언트가 위조할 수 있으므로, 이후 실제 이미지 디코딩 등을 통한 추가 검증이 필요합니다.)  

3. 파일 크기를 제한하지 않으면 어떤 문제가 발생할 수 있습니까?   
: 비정상적으로 거대한 파일이 업로드될 경우, 서버가 이를 읽거나 전처리하는 과정에서 과도한 리소스(CPU, 메모리)를 소모하게 됩니다. 이로 인해 서버 응답이 지연되거나 메모리 부족으로 서버가 다운되어 다른 정상 사용자의 요청까지 처리하지 못하게 될 수 있습니다.  

✅ Day 6 최종 체크포인트  
Q1. API Key 인증이 없으면 어떤 위험이 있습니까? (두 가지 이상)  
무작위 대량 요청으로 인한 서버 과부하(서버 다운), 클라우드 리소스 남용에 따른 막대한 요금 청구, 악의적 사용자의 모델 도용(Model Stealing), 문제 발생 시 요청 출처 추적 불가 등의 위험이 있습니다.  

Q2. Depends(verify_api_key)는 엔드포인트 실행 전에 어떤 일을 합니까?  
실제 엔드포인트 함수가 실행되기 전에 API Key의 유효성을 먼저 검증(인증)합니다. 인증에 성공하면 사용자 정보를 주입하고, 실패하면 엔드포인트 자체를 실행하지 않은 채 즉시 401 Unauthorized 에러를 반환해 요청을 차단합니다.  

Q3. UploadFile 방식이 Base64보다 편리한 점은 무엇입니까?  
이미지를 텍스트로 인코딩할 필요 없이 독립적인 파일 형태로 직접 전송할 수 있으며, 특히 Swagger UI에서 자동으로 '파일 선택' 버튼이 생성되어 테스트가 매우 직관적이고 편리합니다.  

Q4. 파일 업로드 시 크기 제한을 하지 않으면 어떤 문제가 생깁니까?  
비정상적으로 거대한 파일이 업로드될 경우, 서버가 이를 메모리에 올리거나 전처리하는 과정에서 과도한 리소스를 소모하여 전체 서버 응답이 지연되거나 서버가 다운될 수 있습니다.  

Q5. 이미지를 28x28 그레이스케일로 변환하는 이유는 무엇입니까?  
사용하는 MNIST 예측 모델이 학습할 때 사용한 입력 데이터의 규격이 '28x28 픽셀의 흑백(Grayscale) 이미지'이기 때문입니다. 사용자가 어떤 크기나 색상의 이미지를 업로드하든, 모델이 정상적으로 추론을 수행할 수 있도록 입력 크기와 형태를 강제로 맞추는 필수 전처리 과정입니다.
